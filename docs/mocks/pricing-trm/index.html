New prices and the TRM fee

Four mocks: the prices, the distribution unlock, the admin margin view and the database change. Nothing here is built or live.

What I found in the code and the live database

  1. Manager is ₦30,000/month, as you said. One constant.
  2. Solo is ₦7,500 live, not ₦8,000. Solo changes are out of scope, so the mocks keep ₦7,500. Say if you want ₦8,000.
  3. Label is ₦60,000 live, not ₦80,000. It goes to ₦100,000. The ₦80,000 figures in the code are the old legacy plans, which nothing sells now.
  4. Nobody pays today. 0 active subscriptions; one cancelled annual row at ₦800,000 from September. Grandfathering protects future price changes but keeps nobody's price today.
  5. 6 months and yearly cost the same per month. 5 for 6 and 10 for 12 are both 1/6 off (Manager works out at ₦25,000/month either way). Expect most people to pick 6 months. If you want yearly to win, make it 9 months' price.

Things this depends on

  1. The two earlier prompts are not built. No self-serve checkout changes, no "Distribution included" entitlement, no trm_partner_ledger, no acquisition_path. Today a TRM send uses the artist's own TRM plan. This plan builds those pieces on today's code.
  2. TRM has no endpoint to open an account. So "register the team on TRM after payment" is a ledger entry plus a step you or TRM do by hand, until TRM gives us a way. It is the third question in TRM-REQUIREMENTS.md.
  3. Switching monthly to 6 months is new. Today a plan change refuses a change of period. Mock b shows: pay now, the days left on this month come off.
  4. Payments do not record card or transfer today, and the payments table behind the margin view only fills while referrals are switched on. Both change in this plan.

How each column is worked out

  • Cash a month: what the team paid, divided by the months it covers. MRR is the sum.
  • Paystack fee (estimate): card 1.5% + ₦100, the ₦100 waived under ₦2,500, capped at ₦2,000. Transfer to a dedicated account 1% capped at ₦300. Direct transfer to our bank ₦0. Spread over the months paid for.
  • TRM owed: from the ledger for this month. Basis and mode come from env, so the same page shows percent or upfront if you switch.
  • Credits used: credits spent this month × CREDIT_COST_KOBO (₦6.84). Spend, not allowance.
  • Break-even: FIXED_COSTS_MONTHLY_KOBO ÷ contribution per team. The ₦1,500,000 here is a placeholder until you set it.

One migration, additive only

File supabase/migrations/20261022130000_pricing_v3_trm_fee.sql. Applied after your yes, with a backup first. Code ships before it and reads every new column carefully, so either order is safe.

Back up

create table public.subscriptions_backup_20261022 as select * from public.subscriptions;
create table public.subscription_charges_backup_20261022 as select * from public.subscription_charges;

Rollback: nothing to undo. Drop the two backups after 30 days.

Subscriptions: lock the price, allow 6 months

alter table public.subscriptions
  add column if not exists price_locked_kobo bigint null,
  add column if not exists plan_version text null;
-- widen, never narrow: monthly and annual stay valid
alter table public.subscriptions drop constraint if exists subscriptions_billing_interval_check;
alter table public.subscriptions add constraint subscriptions_billing_interval_check
  check (billing_interval is null or billing_interval in ('monthly','six_month','annual'));
-- same widening for pending_billing_interval
-- fill the new columns on existing rows only where empty
update public.subscriptions set price_locked_kobo = amount, plan_version = 'legacy'
  where price_locked_kobo is null;

Rollback: drop the two columns. Put the old check back only if select count(*) from subscriptions where billing_interval = 'six_month' is 0; otherwise those rows need a decision first.

Payments: record how each one was paid

alter table public.subscription_charges
  add column if not exists payment_channel text null
    check (payment_channel is null or payment_channel in ('card','transfer','direct_transfer')),
  add column if not exists billing_interval text null,
  add column if not exists plan_version text null,
  add column if not exists acquisition_path text null;

Rollback: drop the four columns. Old rows stay empty in them; the margin view shows "Unknown" for those.

New table: what we owe TRM

create table if not exists public.trm_partner_ledger (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid null references public.workspaces(id) on delete set null,
  charge_reference text not null,          -- the Paystack reference it came from
  entry_kind text not null default 'period' check (entry_kind in ('period','upfront','adjustment')),
  plan text not null check (plan in ('manager','label')),
  trm_plan text not null check (trm_plan in ('single_artist','label')),
  cost_basis text not null check (cost_basis in ('fixed','percent')),
  billing_mode text not null check (billing_mode in ('monthly_prorata','annual_upfront')),
  fee_annual_kobo bigint null,
  revenue_share_bps integer null,
  service_months integer not null check (service_months between 1 and 12),
  amount_paid_kobo bigint not null,
  owed_kobo bigint not null check (owed_kobo >= 0),
  period_start timestamptz not null,
  period_end timestamptz not null,
  exported_at timestamptz null,
  created_at timestamptz not null default now(),
  unique (charge_reference, entry_kind)    -- a redelivered webhook writes nothing twice
);
alter table public.trm_partner_ledger enable row level security;  -- no policies: server only

Rollback: drop table public.trm_partner_ledger. Export it to CSV first if it has rows; that is what we owe TRM.
