# shadcn/ui in the web app (2026-11-04, v1.246.2, #1071)

Oyin asked for the Up next card on the artist page to be built from shadcn/ui elements. The components now come into `apps/web` the way shadcn means them to: as source files added by its CLI, themed through its semantic CSS variables.

## What is set up

- **`apps/web/components.json`**: style `new-york` (the Tailwind v3 style, since the app is on Tailwind 3.4), base `radix`, aliases `@/components`, `@/components/ui`, `@/lib/utils`.
- **`apps/web/lib/utils.ts`**: shadcn's `cn()` (`clsx` + `tailwind-merge`).
- **`apps/web/components/ui/card.tsx`**: the registry item, unchanged except one line (`border-border`, see below). Dependencies added to `apps/web`: `clsx`, `tailwind-merge`, `class-variance-authority` (what `cn()` and the registry's `cva` components need). A Badge was added and removed in the same pass once the card did not use one; add it back with the CLI when a Badge is needed.
- **Tokens.** shadcn components say `bg-card`, `text-muted-foreground`, `bg-primary`... Those names are mapped in `packages/config/tailwind/preset.js` to CSS variables (`--card`, `--muted-foreground`, ...) that `apps/web/app/globals.css` declares once on `:root` as aliases onto the Urganize palette (`--card: var(--color-bg-surface)`, `--primary: var(--color-brand)`, `--border: var(--border-default)` with each theme's own alpha, and so on). A page's private variables must not reuse these names: the brief invite page's `--card` and `--muted` became `--card-color` and `--muted-text` for that reason. Every theme block in that file sits on the html element, so the aliases follow the theme by themselves. So a shadcn component looks like Urganize without editing the component.
- **No base-layer border rule.** shadcn's `init` normally adds `* { @apply border-border }`, which would recolour every bare `border` in the app (today Tailwind's gray-200). Not done. `card.tsx` says `border-border` itself instead; any other registry component that relies on a bare `border` needs the same one-word edit.

## How to add a component here

The skill shadcn ships for agents (`skills/shadcn/SKILL.md` in github.com/shadcn-ui/ui) says to use the CLI: `pnpm dlx shadcn@latest add <name>` from `apps/web`. From a cloud session the registry host `ui.shadcn.com` is blocked, so the components were served from shadcn's own repository instead: clone `shadcn-ui/ui`, serve `apps/v4/public/r` on a local port (`python3 -m http.server`), and run the CLI with `REGISTRY_URL=http://127.0.0.1:<port>/r`. The files it writes are byte for byte the registry's. From a machine with normal internet the plain command works.

## Traps

- `CardTitle` and friends are plain `div`s in the `new-york` style, so they do not pick up the global `h1, h2, h3, h4` display-serif rule. Good for labels; use a real heading element yourself when the title should be one.
- The legacy `new-york` `CardHeader` uses `space-y-1.5`; the shadcn skill says to prefer `gap-*`, so pass `gap-0.5 space-y-0` when you lay it out as a flex column with a different rhythm.
- Islands that redefine `--color-*` on an inner element (`.cc-island`, `.epk-island`, `.credits-island`) do not change the shadcn aliases, which were resolved on the html element. A shadcn component inside one keeps the page theme.
- The whole-card link pattern (the Up next card): the Card stays the registry's `div`, the visible text is `aria-hidden`, and a stretched `absolute inset-0` Link or button over it carries the name (`aria-label`, with the countdown) and the description (`aria-describedby`). A `button` cannot wrap a `div`, which is why the control sits over the card rather than around it.
- `cn()` lives in `lib/utils.ts`; `components/admin/ui.tsx` re-exports it, so there is one helper.
