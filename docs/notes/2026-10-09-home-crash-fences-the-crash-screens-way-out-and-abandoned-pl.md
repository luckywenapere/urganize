# Home crash fences, the crash screen's way out, and abandoned planner shells (2026-10-09, v1.91.1, no flag)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

Three bugs found by using the live app, fixed in one change.

1. **The crash screen looped.** `app/error.tsx`'s "Back to your rollouts" linked to `HOME_PATH`, which is `/dashboard/home` since Home became the landing page, so a crash on Home led straight back into it. It now goes through `errorBackHref` (`lib/error-back-link.ts`, tested): the catalogue (`/dashboard`) from anywhere, and Home only when the crashed page IS the catalogue, so the link never points at the page that just broke.
2. **Home could crash as a whole.** Reported as a crash right after login on `/dashboard/home` that "Try again" did not clear. **Root cause NOT confirmed**: a read-only check of the same account on production (v1.91.0, `8d3cfbf`) a few minutes later rendered Home normally at desktop width, and no console stack trace was captured. So the fix is containment rather than a cure: every Home block in `HomeBlocks` sits in its own `ErrorBoundary` (`home-block-<key>`), the state view in `HomePageClient` sits in one more (`home-view`, fallback links to the catalogue), and the desktop conversation in `HomeDesktopSplit` in a third (`home-conversation`). `ErrorBoundary` renders no element, so the "no wrapper per block" spacing rule still holds. Each catch reports `app_error_shown` with its scope, so the next occurrence names the block that threw. `describeTaskLine` (the one string function every Home task runs through, changed by #749 that morning) no longer calls `.trim()` on a value it has not checked is a string. If the crash recurs, read PostHog's `app_error_shown` by `scope` first.
3. **Closing the planner left an empty "Untitled rollout".** Picking Single/EP/Album creates the rollout first (`plannerPending`) and opens the intake on it, so Close left a 0/0, undated shell per try. The intake payload now carries `discardIfAbandoned` (set only by the two create flows, `RolloutCreateFlow` and `WorkspaceView`), and dismissing the intake before it builds calls `DELETE /api/releases/[id]?onlyIfUntouchedDraft=1`. The server holds that to `decideDraftDiscard` (`lib/release-draft-discard.ts`, pure and tested), which FAILS CLOSED: still `planner_pending` with no other metadata keys, still `draft`, default title, no date, description or cover, made within the last hour, and zero tasks, task groups, assets, songs, spend lines and collaborators, each counted on the server (a failed count is a no). A refusal is a 409 and the client leaves things exactly as before. Spend is counted through `countReleaseSpendLines` in `release-spend-server.ts`, because `release-spend-guard.test.ts` allows only that file to name the table. The delete is recorded as `release_deleted` with `reason: 'planner_abandoned'`. Note the trade: an accidental backdrop click or Escape also abandons, and the answers given so far go with the shell.

Also: the distribution check strip (`DistributionStatusStrip`) is not mounted on an empty shell (no release date and no activities), where "Fix these before you order distribution" read as an error before anything was done.

**Verified:** the new tests (release-draft-discard, error-back-link, task-line) and the full vitest suite green, `tsc --noEmit` clean apart from the documented `confirmed-action.test.ts` errors, eslint on every touched file with no new findings (the 3 `react-hooks/refs` errors in `WorkspaceView.tsx` are the existing baseline). **NOT verified:** `next build` could not run in the sandbox (Google Fonts answered 409, so `next/font` failed before compiling), nothing ran in a browser, and the discard has never run against a real database.
