# Onboarding v2: preview, opt-in, referral code, paywall, welcome; skippable invites (2026-10-14, v1.129.0, URG-251 + URG-274)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

Founder-approved flow (Linear URG-251 Parts 1, 2, 3, 5 and Oyin's comments; URG-274). The step order is now a LIST in `lib/onboarding-steps.ts` (`onboardingStepSequence`), walked by Next/Back, because several steps are conditional; the numeric ids are stable and are not positions. Who are you? → 0 working on → 1 falls apart → 2 already done → 3 rollout → 4 first move → 5 plan preview (template-plan users only, built client-side from the playbook, `lib/onboarding-plan-preview.ts`) → 6 opt-in → 7 account (+ optional referral code) → 8 paywall → 9 welcome (once per user) → 10 team (skippable).

- **Flag:** `NEXT_PUBLIC_FEATURE_ONBOARDING_V2`, ON unless `'false'` (invite-gate kill-switch pattern; also set true in Vercel Production). Off = the old 0..4 → account → team flow. The paywall is also off under the retired card trial.
- **Opt-in** (`lib/onboarding-optin.ts`, `components/onboarding/OnboardingOptInStep.tsx`): two toggles, both off. Push permission is requested ONLY from the toggle tap (web `Notification.requestPermission`, native `push.request` over the bridge). Choices sit in localStorage (survive the Google round trip) and are attached in `runPostSignupHandoff` after the rollout is made: push subscribed only if the permission is already granted, so the attach can never prompt; email saved via `PATCH /api/user/marketing-consent` (open route). Showing the step writes `urganize.push-prompt.onboarding-shown`, and `decidePushPrompt` then skips the in-app soft ask (a granted device is still repaired). `?setup=1` saves directly on tap. **Migration** `20261014160000_profiles_marketing_email_consent.sql` (`marketing_email_consent` default false + `marketing_email_consent_at`) was applied to production on 2026-10-14 with Oyin's approval. Marketing only: nothing transactional reads it, and no marketing sender reads it yet either.
- **Referral code:** shown only when `NEXT_PUBLIC_FEATURE_REFERRALS` is on. Prefilled from the stored `?ref=`; `rememberTypedReferralCode` writes the same store, so `reportReferralCode` → `POST /api/referrals/attach` is unchanged. Malformed = one calm line, never blocks; an unknown code is refused quietly by the server as before.
- **Paywall** (`lib/onboarding-paywall.ts`, `components/onboarding/OnboardingPaywall.tsx`): headline exactly "Run your next release like a pro.", logo strip "Built with people from" (never "Trusted by"; the masks are copied into `apps/web/public/images/affiliations`), up to 5 cards led by their "falls apart" answers with the URG-251 testimonials VERBATIM from `apps/homepage/content/testimonials.ts` (a test holds them equal), scratch users lead with team alignment and never see the week-by-week card. Plan pre-selected from the persona (independent_artist → Solo, label_ar → Label, everything else → Manager) via `TierPlanPicker`, prices from `PRICING_TIERS` (yearly = `ANNUAL_MONTHS_BILLED`; Part 4 "Save 55%" is ON HOLD and absent). No skip, no close. The trial is the existing 3-day no-card team trial granted at team creation, so "Start my free trial" saves the plan choice (`TeamWall` opens on it later) and moves on. iPhone app: no prices shown (`isIOSApp()`).
- **Welcome** (`lib/onboarding-welcome.ts`): localStorage per user; opens nothing the first session keeps quiet.
- **URG-274:** onboarding's team step was already skippable; Skip (or Send with no valid email) now also writes `urganize:invite-gate:onboarding-skipped`, and `InviteGate` stays away during the first session and for that skip window (`isInviteGateHeldBack`). An invite still clears it for good.
- **Pinned task:** `lib/pinned-confirm-date.ts` matches "confirm the release date" by playbook task id (`w8_/w13_/w17_confirm_release_date`, plus `onboarding_confirm_release_date`), title only as a narrow fallback, and pins it above the plan (inline banner slot and full-screen timeline) on the rollout onboarding made in this browser (first-session record) until it is done. A start-from-scratch ONBOARDING rollout (`plan: 'blank'`, `source: 'onboarding'`) is seeded server-side with exactly that one task; an in-app blank rollout stays empty.
- **Analytics:** `onboarding_preview_viewed`, `onboarding_optin_viewed/_toggled/_choices`, `onboarding_referral_invalid`, `onboarding_paywall_viewed`, `onboarding_paywall_card_swiped`, `onboarding_trial_started`, `onboarding_paywall_chat`, `onboarding_welcome_viewed/_go`, `onboarding_invite_skipped`.
