# Cross-generation model fallback (2026-10-11, v1.107.1)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.
On 2026-10-11 RodiumAi returned `502 provider_unavailable` for every gpt-5.4 / 5.5 / 5.6 model at once (gpt-5, gpt-5.2, gpt-5-mini, gpt-5.4-mini, gpt-4o-mini, gpt-4.1 still answered). The planner surface's floor is `pro` and its rung held only `gpt-5.4` + `gpt-5.6-terra`, so every plan's AI layer failed in under a second (`ai_usage_events.failure_kind = 'server'`) and plans fell back to the playbook. Each rung in `lib/ai/model-ladder.ts` now ends on an older-pool sibling: standard `gpt-5-mini`, pro `gpt-5`, max `gpt-5.2`, priced in `lib/credits/model-prices.ts`. A server hop now stays inside the rung (planner: 5.4 → 5.6-terra → 5), within its 2 hops. No env change needed; an `AI_LADDER_<RUNG>` override still replaces a rung's list. To diagnose a repeat: `curl https://api.rodiumai.io/v1/chat/completions` with each model (the key is injected for that host) and read `ai_usage_events` for `failure_kind`.
