The homepage hero's product visual is an animated loop built with the Stageshow kit (`docs/notes/2026-11-01-stageshow-kit.md`): add a release, the plan appears, the tasks land on the team, back to Rollouts with the new release on top. It replaced the static Rollouts capture and its Artists | Rollouts tabs (`HeroShotTabs.tsx`, URG-378, deleted). Founder approved the mock in advance (#951).

## Files

- `apps/homepage/app/components/landing/hero-loop/HeroLoopDemo.tsx`: the stage and its script, from the approved mock. Only ever loaded by `HeroLoop.tsx`.
- `hero-loop.css`: the scene's styles. Colours are `--ug-*` tokens with a dark set under `html[data-marketing-theme="dark"]`, unlayered so they beat the kit's own theme values and switch with the site toggle without a re-render.
- `HeroLoop.tsx`: the client host. The poster (server-rendered child) sizes the frame; after mount, and only without reduced motion, it imports the demo with `next/dynamic` (`ssr: false`) and cross-fades it in once the stage has painted (`data-playing` on `.hero-loop`, CSS in `globals.css` under "THE HERO LOOP").
- `poster.ts` and `public/images/hero-loop/*.webp`: the four stills (desktop and phone, light and dark).

## Traps

- **The phone design is picked by media query, not by the stage's width.** The kit picks its compact layout from its container width, but the poster `<picture>` can only switch on the viewport (`max-width: 639.98px`). So `HeroLoop` reads the same media query and passes `compact` to the demo (with `below: Infinity`), keeping the still and the loop on the same design at every width.
- **The stills are the loop's own last frame.** If `TASKS`, `ROLLOUTS`, the copy or the styles change, retake all four, or the cross-fade jumps between two different plans. `POSTER.owners` is one past the last row on purpose, so no row wears the "just landed" highlight in the still.
- `fill` lets the stage grow past its 1000px design to the frame's 1344px. The desktop stills are 2700 wide so that still looks sharp at 2x.
- The stage crops the window at its foot (`.ug-stage { overflow: hidden }`), like the mock.

## Retaking the stills

1. Add a throwaway page `apps/homepage/app/hero-poster-tmp/page.tsx` (client) that sets `document.documentElement.dataset.marketingTheme` from `?theme=`, hides `header, footer, nav, nextjs-portal`, makes `html, body` transparent, and renders `<HeroLoopDemo theme compact />` in a fixed box 1000px wide (358px for `?layout=phone`).
2. Run the homepage dev server and capture with headless Chrome. `--force-prefers-reduced-motion` makes the stage show its poster state:

   `chrome --headless=new --force-prefers-reduced-motion --default-background-color=00000000 --hide-scrollbars --window-size=1000,560 --force-device-scale-factor=2.7 --virtual-time-budget=8000 --screenshot=hero-loop.png "http://localhost:<port>/hero-poster-tmp?theme=light"`

   Desktop: 1000x560 at 2.7. Phone: `--window-size=358,540 --force-device-scale-factor=3` with `&layout=phone`. Repeat with `theme=dark`.
3. Convert with sharp: `.webp({ quality: 82, alphaQuality: 90, effort: 6 })` into `public/images/hero-loop/`, then update the sizes in `poster.ts` if they changed. Delete the throwaway page.
