# Promo channel directory in the rollout (2026-10-11, v1.117.0, GitHub #833, no flag)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

From the Oct 11 demo with a Nigeria-based manager: X music communities, SoundCloud networks, online and FM radio and blogs are the underused way to push music without a media budget. **No feature flag** (shipped on, per the founder's standing "always ship them on"). One migration, `20261011190000_promo_channels.sql`, **not applied to production when this shipped**: until it is, the scene says "Promo channels are coming soon.", the plan banner line stays hidden, a suggestion answers 503 and `/admin/promo-channels` says the table is missing. Nothing crashes.

- **Where it lives.** A rollout scene, `?scene=promo`, menu row "Find promo" (Megaphone), ranked right after Pitch and the pitch kit in `lib/release-menu.ts`, always present (no flag owns it, like Distribute). `components/promo/PromoChannelsSection.tsx`: country chips (All / Nigeria / UK / Online, opens on Nigeria, `DEFAULT_PROMO_COUNTRY`), type chips (only kinds that have a listed channel), "Good fits" then "All channels" as the Pitch screen's square tile grid (2/3/4 columns, `CuratorFace` gradient tiles, Free/Paid badge), and once a tile is picked one card: how to submit, contact, lead time, cost, a due date and "Add to plan". "Suggest a channel" sits at the foot. Not cached (`promo` is outside `CacheableSceneName`, `SCENE_PERSISTED.promo = false`).
- **Data.** `public.promo_channels`: kind (`x_community`, `x_spaces`, `soundcloud`, `online_radio`, `radio`, `blog`; text + CHECK), country (ISO alpha-2, null = online/anywhere), city, genres, how_to_submit, contact, url, lead_time (the channel's own words), lead_time_days (only when that gives a number), cost (`free`/`paid`/null), source_url, status (`listed`/`pending`/`rejected`), suggested_by, suggestion_note, reviewed_at/by, slug (seed idempotency). RLS: one SELECT policy for `authenticated` on listed rows; no write policy, every write is a service-role route. A test holds the CHECK list to `PROMO_CHANNEL_KINDS` and the policy shape.
- **Seed (15 rows, each checked on the channel's own page on 2026-10-11, `source_url`):** Album Talks (X), Repost Exchange (SoundCloud), NMC Signal (London online radio), Cool FM 96.9 Lagos and Abuja, Soundcity Radio 98.5 Lagos and 96.3 Abuja, The Beat 99.9 FM Lagos, BBC Radio 1Xtra, BBC Music Introducing, Colourful Radio, Notjustok, Naijaloaded, The NATIVE, OkayAfrica (via Groover). Fields a channel does not publish are empty, never guessed. **Flagcode radio, named in the issue, could not be identified on the web and is not seeded**; there is no X Spaces host seeded either. Both can come in through suggestions.
- **Adding to the plan** is an ordinary `POST /api/tasks` through `useTaskStore.createTask` (which gained an optional `description`): title `promoTaskTitle` ("Submit to …", "Post on …" for SoundCloud, "Get on …" for Spaces), description `promoTaskDescription` (how, contact, link, lead time, cost), due `promoTaskDueDate` = release day minus lead_time_days, or minus `DEFAULT_PROMO_LEAD_DAYS` (21) when the channel does not say, never before today, a week out with no release day. A channel already on the plan is matched by that title and shows a check.
- **Suggestions.** `POST /api/promo-channels/suggestions` (any active team account): name, kind, country, an http(s) link, optional how-to-submit; `parsePromoSuggestion` validates; at most 10 pending per person. Reviewed at `/admin/promo-channels` (AdminNav + the hub's Operations group): List it / Reject for waiting rows, Take down for listed ones, each a conditional update on the expected status (409 if someone else moved it).
- **"The AI plan suggests channels" is deterministic, not a model call.** The hybrid planner's AI delta (`PlannerAiDelta`, `sanitizePlannerDelta`) only edits and adds playbook tasks under strict caps; teaching it about an external directory would have meant new prompt context, a new delta field and new gate rules on the most guarded path in the app. Instead `suggestPromoChannels` (pure, tested) ranks listed channels by the rollout's genre (`release_metadata.genre`) and country: in-country before online, then free, unknown, paid, then name. The Promo scene's "Good fits" and a "Promo that fits: … / Find promo" line in `PlanBuiltBanner` both use it, so the plan names up to 3 and opens the scene. If a model-picked list is wanted later, the place is a new optional field on the delta, not a second path.
- **Routes:** `GET /api/releases/[releaseId]/promo-channels` (team read access, enlisted in `release-access-guard.test.ts`; `ready: false` with no channels when the table is missing, via `isMissingTableError`, which returns no SQL and is not the deprecated fallback), `POST /api/promo-channels/suggestions`, `GET/PATCH /api/admin/promo-channels` (`verifyAdmin`).
- **Verified:** `lib/promo-channels.test.ts` (filtering, genre fit, ranking, due dates, titles, suggestion validation, missing-table detection, migration agrees with code), updated menu and guard tests, the full suite green, `tsc --noEmit` clean. The migration ran twice on PGlite (idempotent, 15 listed rows, CHECK refuses an unknown kind). **Not verified:** nothing in a browser or against a real session; the screens follow the Pitch grid's classes but have not been looked at at 375px or 1440px.
