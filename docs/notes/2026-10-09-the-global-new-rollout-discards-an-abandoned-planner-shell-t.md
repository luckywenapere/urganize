# The global "+ New rollout" discards an abandoned planner shell too (2026-10-09, v1.92.1, no flag)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

v1.91.1 and v1.91.3 made closing the planner early discard the rollout a create step had just made for it, but only on the create paths in `RolloutCreateFlow` (Home, the UrgAns page) and `WorkspaceView`. `AppShell`'s global `CreateReleaseModal` (the "+ New rollout" taps) still opened the intake without `discardIfAbandoned`, so closing the planner there left an empty "Untitled rollout" behind.

- **One builder, every path.** `buildCreatedRolloutIntake` in `lib/release-draft-discard.ts` returns the intake payload for a just-made rollout (`source: 'empty_state'`, `discardIfAbandoned: true`, `createdTitle` from the modal's `savedTitle`, and the type prefill only when one was picked). `AppShell`, `RolloutCreateFlow` and both `WorkspaceView` branches now call it instead of spelling the payload out, so the four can no longer drift apart.
- **Safety unchanged.** Nothing about the discard itself changed: the planner still sends `DELETE /api/releases/[id]?onlyIfUntouchedDraft=1`, and the server still holds it to `decideDraftDiscard` (planner_pending, draft, default or exactly-as-created title, no date/description/cover, under an hour old, zero tasks, groups, assets, songs, spend and collaborators; fails closed). A rollout with any activity, date or edit is kept. The AppShell path does not navigate, so after a discard the person stays where they were and the catalogue reloads (the dismiss handler's existing `loadCommandCenter({ force: true })`).
- **Tests:** `lib/created-rollout-intake.test.ts` (the builder's payload; a source scan that the set of files mounting `<CreateReleaseModal` is exactly the three known hosts, and that every `openIntake(...)` with a payload inside each host's `onCreated` goes through the builder). `lib/rollout-create-title-guard.test.ts` now checks AppShell too and counts `savedTitle` per builder call. Mutation: restoring `main`'s `AppShell.tsx` fails both.
- **Not verified in a browser or against a real database.** Preview pass: from a page other than the catalogue, tap "+ New rollout", pick Single (optionally name it), Create, close the planner at Question 1, and confirm the rollout is gone from the catalogue; repeat, add an activity or rename it in a second tab before closing, and confirm it is kept.
