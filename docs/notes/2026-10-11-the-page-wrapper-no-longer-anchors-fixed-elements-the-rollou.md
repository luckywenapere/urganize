# The page wrapper no longer anchors fixed elements; the rollout chat pins over the phone keyboard (2026-10-11, v1.115.6)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

**Root cause of a whole class of "fixed panel in the wrong place" bugs:** AppShell wraps every page in `.app-layout lazy-fade lazy-fade-in`, and `.lazy-fade-in` rested at `transform: translateY(0)`. Any transform other than `none` makes the element the containing block for every `position: fixed` descendant, so fixed panels inside the page anchored to the PAGE, not the screen (only for users without reduced motion, whose block already said `none`). Symptom that surfaced it: Notifications opened from More after scrolling showed at the top of the page, off screen. The fix is one declaration, `.lazy-fade-in { transform: none }`, chosen over portalling each overlay because both classes are applied in the same render (the fade never actually animated), it fixes every fixed descendant at once including ones nobody has reported, and it needs no DOM moves (a portal remounts its subtree, which would drop focus from a chat field and close the keyboard). Existing portals (HomeAskBar, BottomBar's More sheet, the rollout menu sheet, dialogs) stay; they are harmless. `lib/fixed-containing-block-guard.test.ts` holds `.lazy-fade-in`, `.app-layout`, `.app-shell-frame` and AppShell's wrapper classes free of transforms, filters, backdrop-filters, `will-change`, `contain` and `perspective`. Comments elsewhere that say ".app-layout carries a transform" describe the past.

**Rollout Chat on iOS with the keyboard open:** the box stayed in the page flow and was sized to end at the visual viewport's bottom. iOS scrolls the page to reveal the focused field, then the box shrank by the keyboard's height under that scroll (and the frame's min-height dropped), so the visible region showed empty background below the box while the composer sat behind the keyboard. Now (`lib/release-chat-layout.ts`, `ReleaseChatSection.tsx`): on a phone with the keyboard up the box is restyled in place (never portalled) to `position: fixed`, top = `visualViewport.offsetTop` + safe-area top, height = `visualViewport.height` - safe-area top, so the composer is the last thing above the keyboard and its accessory bar and the list fills the rest, scrolled to the newest message. A slot keeps the box's flow height so nothing behind it reflows, and `usePinnedChatHeight(ref, frozen)` stops re-measuring while pinned. The bottom bar already hides while the keyboard is open (`:root[data-keyboard-open='true'] .mobile-nav-bar`). On a phone the chat takes the shared body scroll lock while mounted and restores the page's scroll position when the keyboard closes. Desktop (lg+, including an iPad with a keyboard) keeps the flow layout untouched. **Not yet tested on a real iPhone.**
