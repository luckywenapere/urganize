## 2. Planner v2: UrgAns writes the plan

Flag `NEXT_PUBLIC_FEATURE_PLANNER_V2`, ON unless `'false'`. Off = the v1 playbook intake, untouched (`PlannerIntakeModalV1`).

**Files.** `lib/planner-v2/` — `answers.ts` (answers, options, Naira bands, legacy intake mapping), `steps.ts` (which questions show, Continue blockers), `moves.ts` (menu: Nigeria pack + every playbook task), `plan.ts` (schema + lenient parser), `prompt.ts`, `validate.ts` (the fence + `repairPlanV2`), `fallback.ts` (quick plan), `write-plan.ts` (model → validate → one retry → repair → fallback), `server.ts` (preview/apply), `planner-v2.test.ts` (fixtures: the 27 real intakes, anonymised). `lib/ai/wallet-alert-server.ts`. Route `app/api/releases/[releaseId]/plan/v2/route.ts`. UI `components/planner/PlannerV2Modal.tsx`, switched in by `PlannerIntakeModal.tsx`.

**Questions** (one per screen, "Question N of M", M = questions actually shown). The planner never depends on a release date (Oyin, 26 Oct 2026): there is no "When does it drop?" question.
1. Where's the music right now? Still making it / Finished, not out yet / Already out. Finished → chips Cover art / Video / Distributor. EP/album and not out → "Drop a single first?". A Single/EP/Album row shows only when the caller did not prefill the type.
2. Already out only: "When did it come out?" (This week / This month / Earlier + optional exact day), skipped when the rollout row has a past date. The plan is a push plan from today.
3. What would make this a win? One pick + "Say it your way". Radio/DJs or Shows → "Which cities?".
4. How much can you spend on promo? ₦0 / Under ₦100k / ₦100k–₦500k / ₦500k–₦2m / Over ₦2m + optional exact amount.
5. Where do your fans listen and scroll? Audiomack, Boomplay, Spotify, TikTok preselected; Apple Music, YouTube, Instagram, X, Radio.
6. Who's doing the work? Just me / Me + 1–3 people / Full team, + optional "Anything UrgAns should know?".
So music not out sees 5 screens (Oyin asked for "4 + note"; the 5 asked-for topics do not fit 4 screens without merging two, which is a call for Oyin). Dropped: "When does it drop?", "Who's the artist?", "What should the plan cover?". `DateStep` from the v1 intake is exported but no longer used by v2.

Credits footer on the last question is one short line: "Uses about N credits" (or "Your first plan is free."). No explainer lines.

**No date: relative plan.** A rollout with no date gets a plan anyway (`resolvePlanV2ReleaseDate` returns null; `PlanV2Context.releaseDate` is nullable). The window is day -56 to day 42 relative to a release day still to be picked (`UNDATED_MIN_OFFSET`); no "before today" rule; distributor task required, release-day task not (it comes with the date); min size 6 (`UNDATED_MIN_TASKS`); the weekly pace rule still applies. Each task has `now` (prep that needs no date: mastering, artwork, distributor upload, press kit, pitch list). The prompt tells UrgAns to leave editorial deadlines, radio/OAP/DJ timing and release-day/after-release pushes for later. Saved by `insertUndatedPlan` (`lib/planner-v2/server.ts`): the usual plan rows with `due_date` null and `metadata.planner_v2 = { offset_days, now, when }`; phase grouping is unchanged (metadata.phase from the offset). The task list reads `Task.relativeWhen` ("Now", "4 weeks before", "Release week", "Release day", "After release"; `lib/planner-v2/when.ts`) where it would have said "No due date".

**The date anchor is the existing "Set your release date" row** (SetReleaseDateCard → `POST /api/releases/[id]/schedule`). After the date saves and any dated plan is aligned, `datePlanV2OnSchedule` (`lib/planner-v2/dates-server.ts`): (1) gives every undated task `release date + offset` (before today → `compressed_runway`, reads as catch up); (2) once per rollout (release metadata `planner_v2_dates_added`, claimed before the call) asks UrgAns for the date-dependent tasks on the router's `planner_quick` surface (gpt-5.4-mini, 20 s timeout, 30 s deadline, not charged, usage logged), cleaned by `cleanDateAdds` (not before today, picked channels, no repeat of the board, spend within what is left, ₦0 free, pace with the dated board), code-built `fallbackDateAdds` if the gateway fails or nothing passes. They are inserted as ordinary plan rows and appended to the plan document. Toast: "Dates added. 4 new tasks." (`lib/schedule-release-outcome.ts`). A later date change finds no undated tasks and the flag set, so `alignPlanToReleaseDate` just shifts due dates; nothing is generated twice. A date set before planning is used directly (the plan is dated, as before). The schedule route now has `maxDuration = 60`.

**Generation.** Through the model router (`lib/ai/routed.ts`), by surface: `planner` (gpt-5.4, `AI_PLANNER_MODEL` pins) for a first plan and "Try another angle", the new `planner_quick` surface (gpt-5.4-mini, floor standard, 1 hop, `AI_PLANNER_QUICK_MODEL` pins; id in `lib/ai/planner-model.ts`) for Tweak and the date adds; temperature 0.9, reasoning low, JSON schema, 6k output cap, 38 s per attempt, 52 s deadline. Output: `built_for` summary, Naira budget lines, 10–18 tasks. `validatePlanV2` checks dates vs release day/today, distributor + release-day tasks (not for already out), dependency order and cycles, spend ≤ budget, ₦0 = free and no paid words, channels ⊆ picked, size and pace per team (≈3 a week solo). One retry sends the issue list only; then `repairPlanV2`; else the quick plan (`QUICK_PLAN_NOTICE`, Retry button on the preview).
- Repair trap (fixed while finishing): a playbook can hold several `distribution` tasks; only ONE distributor task and ONE release-day task may bypass the weekly pace cap, or the quick plan breaks its own pace rule.
- Empty wallet: `insufficient_balance` → quick plan, a loud log, and at most one founder email a day (`ai_wallet_empty` billing event + `FounderAlertKind`). No migration: `billing_events.type` is free text.

**Preview → apply.** `POST …/plan/v2 {action:'preview'}` writes no rows (a model call is charged through the existing embedded credit hold/settle; first plan free). `{action:'apply'}` re-validates the plan the browser sent, then saves through the existing plan document (`release_plan_drafts.doc`, `core_only`, `planner_v2` card) and `instantiateDraftPlan`. Both refuse a Solo team with `plan_required` (same entitlement as the embedded action) and an auto build in flight.

**Open.** RodiumAi wallet needs a top-up or every plan is the quick plan. ₦ ranges in `moves.ts` are first guesses for Oyin to review. The 10-case eval for moving first plans to mini is not built. No soft-delete trail yet for the learning loop.
