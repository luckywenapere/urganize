# Send to TRM (URG-392, v1.160.0, 2026-10-19)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

The rollout's Distribute step can now deliver a **single** to TRM Distro through TRM's Partner Distribution API (openapi 1.2.0, production only, no sandbox). Founder approved the mocks and the build on Oct 19, 2026. The entry stays "Distribute" (TRM is named only on the send action and the status).

- **Code:** `lib/trm/webhook.ts` (pure: HMAC check + tolerant payload reader), `lib/trm/client.ts` (server only: client_credentials token cached until expiry, Idempotency-Key on every write derived from the exact body, `TrmApiError`), `lib/trm/release.ts` (pure: TRM's required fields as a checklist, defaults, the ReleaseInput builder, status/chip/progress), `lib/trm/server.ts` (DB + orchestration), routes `app/api/webhooks/trm`, `app/api/releases/[releaseId]/trm` (GET payload, POST actions settings / interest / prepare / presign_master / complete_master / submit / refresh), `app/api/trm/health` (read-only token + /capabilities check, internal accounts only). UI: `components/releases/trm/*`, mounted by `DistributionSection` (kill switch `NEXT_PUBLIC_FEATURE_TRM_SEND=false` falls back to the old handoff + partner cards).
- **Tables (migration `20261019120000_trm_send.sql`, additive, applied Oct 19):** `distribution_submissions` (one row per rollout per partner: TRM release id, status incl. our own `preparing` / `needs_account` / `waitlisted`, history, settings, asset ids, UPC/ISRC, artist TRM email) and `partner_webhook_deliveries` (dedupe by `(partner, delivery_id)` primary key; refused deliveries kept with header names and a capped body, max 50/hour). RLS on, no policies: service role only. TRM rejections reuse `distribution_rejections` (partner `trm`) and become `tasks` tagged `metadata.trm_rejection`.
- **The master never touches Urganize:** the browser hashes it (SHA-256), the server presigns, the browser PUTs straight to TRM's R2, the server completes. Cover art goes server-side from our storage, re-sent only when the artwork changes.
- **Open to every team** (founder, Oct 19, 2026, 03:10 WAT: "ship everything and open it up"). **A send bills the artist's own TRM account/plan, not Urganize** (founder, same night); the send sheet says "Uses the artist's TRM plan". `canSendToTrm` is the one gate every TRM call passes (TRM configured + optional `TRM_SEND_ALLOWED_EMAILS` kill switch: when set, only those emails reach TRM and everyone else's Send records `trm_send_interest`, "opens soon", with zero TRM calls).
- **Webhook:** `X-TRM-Webhook-Signature` = HMAC-SHA256(`timestamp + "." + raw body`, `TRM_WEBHOOK_SECRET`), timestamp within 5 minutes. TRM documents nothing else (no timestamp/delivery header names, no encoding, no sample body), so the verifier accepts hex or base64, `sha256=`/`v1=` prefixes or a `t=,v1=` list, and looks for the timestamp in `x-trm-*timestamp*` headers; the HMAC itself is never loosened. Once TRM's real payload is seen in `partner_webhook_deliveries`, pin the reader.
- **Env (Vercel Production, urganize):** `TRM_CLIENT_ID`, `TRM_CLIENT_SECRET` (credential "Urganize server (Hark build)"), `TRM_WEBHOOK_SECRET` (rotated Oct 19 in the TRM portal), optional `TRM_SEND_ALLOWED_EMAILS` (kill switch, unset = open), `TRM_API_BASE_URL`.
- **Defaults** (one "Rights & policies" row, editable): label Independent (or the metadata label), copyright = artist + release year, stores `["all"]`, country of recording Nigeria, owns recording + collects publishing Worldwide, YouTube/Facebook Monetize, SoundExchange Claim from Inception, royalty splits = master splits when filled, else 100% to the artist. Open with TRM: canonical store ids, rejection payload shape, whether these defaults are acceptable.
- **Not built in v1:** EP/album (shows "Singles first"), takedown UI, the rollout-line "Sent to TRM" strip, automatic artist TRM account creation (no endpoint).
