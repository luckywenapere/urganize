# First-session fixes from PostHog replays (2026-10-11, v1.109.0, live at merge, no flag)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

From a review of new users' first sessions in PostHog (rage clicks, dead clicks, quick closes, slow INP). Each fix and its root cause:

- **No auto-starting tour.** The catalog ("welcome") tour auto-started on first visit and FirstReleaseFocus waited for it; on a phone two of its three steps resolved to the same Catalogue tab, so Next looked dead and new users bailed. The catalog tour and `useCatalogTourAutoStart` are removed (its "Show me the catalog again" help-menu row went with it); FirstReleaseFocus shows straight away. The rollout tour stays, startable from the help menu ("Show me a rollout again") and Settings → Guided tours. Its last step's "Go to Team" used to end the tour and go nowhere; a step can now carry `action: 'open-team'`, which opens Settings on the Team segment.
- **Planner intake validation.** Taps on a disabled Continue did nothing visible (a 50%-opacity brand pill reads as enabled). `lib/planner-intake-validation.ts` (pure, tested) returns the reason per step; the modal shows it inline under Continue, which is `aria-disabled` rather than `disabled` so a tap explains itself. Option rows are full-width, at least 52px tall, `touch-manipulation`, with children `pointer-events-none` so a tap anywhere lands on the label. The selected fill is now `bg-brand/10`: the old `bg-brand/8` is off Tailwind's opacity scale and generated no rule, so a choice showed only a thin border.
- **Distribution checklist.** "Fix these before you order distribution (N)" was one list closed within seconds. It is now `DistributionChecklist` with "X of N done": records are per release in localStorage (`lib/distribution-checklist.ts`, pure, tested), warnings can be ticked by hand, errors tick themselves only when the server check stops raising them. Event `role_gap_fixed` keeps the lowercase snake_case convention. The order route still refuses on any error; the checklist decides nothing. The separate **RoleGapsPanel** (unassigned jobs) is unchanged.
- **Mobile tap targets.** ShareSheet tabs 44px and stacked on narrow screens, inputs 16px (stops iOS zoom); TaskDetailView Close/Delete 44px in a sticky bar; BottomBar icons `pointer-events: none` so the tap lands on the link.
- **Perf.** The nine Settings segments and TeammatesSection are wrapped in `memo`, and `useTeammates().refetch` is a stable `useCallback` (it was a fresh arrow each render, defeating the memo); this targets a 304ms INP in Settings → Team. Space Mono is `preload: false` (not used on /auth). CommandBar and FloatingUrgAns are `next/dynamic` (SSR kept) so their code leaves the /auth first-load bundle.
- **Not changed on purpose:** some dead clicks (the Status tab, the Shows circle) look like PostHog false positives (the click did navigate or open), so they were left alone.
- **Not verified:** nothing has run in a browser against a real session; checks were unit tests, lint, tsc and a production build with a mocked font and dummy Supabase env.
