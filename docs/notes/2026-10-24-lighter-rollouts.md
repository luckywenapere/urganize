# Lighter rollouts: no lock, offers on a sign, origin on every rollout (2026-10-24, v1.174.0)

Founder approved mock `lighter-rollout-v1` ("Yes build", "Do your plan too"). Goal: stop forcing new teams to make a rollout, so rollout numbers mean real releases, and let people use Opportunities, the Directory and the rest without one. **Supersedes the first-rollout focus (2026-10-10)** and the timed first-release prompt (2026-08-28).

## What changed

1. **Onboarding: "Nothing planned yet".** Step 0 ("What are you working on?") has an OR option under Single/EP/Album: "Nothing planned yet / Look around first. Plan a rollout later." It sets `draft.nothingPlanned` (never true beside a release type). `onboardingStepSequence({ nothingPlanned })` keeps persona, 0, 1 (falls apart: about how they work, and it leads the paywall), opt-in, account, paywall, welcome, invite; it drops 2 (already done), 3 (rollout), 4 (first move) and 5 (preview). `runPostSignupHandoff` skips the `POST /api/releases` and goes straight to `finishHandoffAfterRelease` (opt-in, then paywall/welcome/invite or `finishToDashboard`), so the onboarding PATCH and its welcome email still run, and it lands on Home (no created rollout). Buttons read "Create account" / "Continue" instead of "... rollout". Survives the Google round trip (sessionStorage draft) and email confirmation (`np: 1` in the metadata draft; `fromMetadataDraft` accepts it with no title, date or type).
   - **Recorded on the profile** as `profiles.onboarding_stage = 'nothing_planned'` (`ONBOARDING_STAGE_NOTHING_PLANNED`, `isOnboardingExploring(row)` in `lib/onboarding.ts`). Free-text column, so **no migration**. It is not an `OnboardingStage` (nothing maps it to a playbook task); `normalizeOnboardingState` reads it back as a null stage. The PATCH route accepts it through `isOnboardingProfileStage`.
2. **The lock is gone.** Deleted: `components/releases/FirstReleaseFocus.tsx` (bar, link catching, auto-opening dialog), `lib/first-release-focus.ts` + test, the `html[data-release-focus]` nav dimming in `globals.css`, `useFirstReleasePrompt` + `lib/first-release-prompt.ts` + test (already superseded) and its three call sites. Kept: `useFirstReleaseRequired` / `lib/first-release-required.ts` (the zero-rollout predicate, fails toward false).
   - **Home card** `components/home/RolloutOfferCard.tsx`: "Got a release coming?" / "Plan it here when you are ready." / Plan a rollout + Not now. Shows for a non-curator, onboarded team with zero rollouts (`decideHomeRolloutCard` in `lib/rollout-offer.ts`). Not now is remembered per user in localStorage (`urganize.rollout-offer.home-dismissed.<userId>`), so a new device shows it once more. Flag `NEXT_PUBLIC_FEATURE_ROLLOUT_OFFER`, ON unless `'false'`; off hides only the card.
   - **The plan choice is reusable**: `components/releases/PlanChoiceDialog.tsx` (`PlanChoiceDialog` + `PlanChoiceHost`, the one copy mounted in `AppShell`). Any offer calls `useShellStore.openPlanChoice({ artistId? })`; choosing calls `openCreate(plan, { origin: 'hint', artistId })`, which opens the shell's `CreateReleaseModal` past its chooser.
3. **Offers come back only on a sign** (these show even after Not now on Home):
   - **UrgAns**: a ROLE rule in `lib/chappi/system-prompt.ts`: when the user mentions an upcoming release and `list_releases` has no matching rollout, offer once in one line; create nothing until yes; do not push a zero-rollout user otherwise. On yes it passes `from_offer: true` to `generate_release_plan` or `create_release`, which send `origin: 'hint'`.
   - **Pages that need a rollout**: `components/releases/NeedsRolloutEmpty.tsx` on Distribute (empty list) and Pitching (zero rollouts now shows the empty state instead of bouncing to the catalogue; a failed load still bounces). Press kits are hidden (redirect to Artists), so nothing there.
   - **Artist release date: NOT BUILT.** `artists` has no release-date or upcoming-release field. The artist page already has New rollout on its Rollouts card.
   - **Opportunities: nothing to change.** `releaseId` is already optional in `parseOpportunityCreate`/`parseOpportunityPatch` and the page never asks for one.
4. **Origin on every rollout** (`lib/rollout-origin.ts`): `releases.metadata.origin` = `'onboarding'` (source `onboarding`, cannot be claimed by others) | `'hint'` (caller sent `origin: 'hint'`) | `'choice'` (everything else, including the test path). A jsonb key beside `created_source` (2026-10-17), so **no migration**. `readRolloutOrigin` reads old rows as `'unknown'`, except `created_source = 'onboarding'` → `'onboarding'` (the one safe inference; in-app creates between 10-17 and 10-24 may have been forced by the lock, so they stay unknown).
   - **Scoreboard**: `ScoreboardRelease.origin`, `rolloutOriginSummary()` and `Scoreboard.rolloutOrigins` (`total`, `byChoice`, `fromHint`, `fromOnboarding`, `unknown`; real rollouts only). `/admin/scoreboard` shows a "Rollouts by choice" card. **Onboarding rollouts from before 2026-10-24 are mixed**: sign-up required one, so some were real and some only made to get in. Optional on `Scoreboard` because a cached board from before has none.

## Traps

- `lib/rollout-vocabulary.test.ts` allows "Got a release coming" and "an upcoming release" by exact phrase: there "release" is the music, before a rollout exists.
- `from_offer` is in `PROMPT_PROSE` in `system-prompt.test.ts` (an argument, not a tool).
- Analytics: `rollout_offer_plan` (`from: home | empty_state`), `rollout_offer_dismissed`.
- An invited teammate on a team with zero rollouts also sees the Home card (same as the old lock); it is quiet and dismissible.
- Manual pass needed: sign up with "Nothing planned yet" (email and Google), check Home, the card, Not now, Plan a rollout → both choices, and an UrgAns chat that mentions a release.
