From the Profiles and Directory spec. Search results are never ranked. Two shelves sit above them, only in the default view (no query or filter set), and a shelf with nobody on it is not drawn at all, heading included. Migration `20261010140000_featured_shelves.sql` (**apply it before merging**; the routes read both tables).

- **Featured**: hand-picked by Urganize at `/admin/featured` (ADMIN_EMAILS on every method, no flag, in the admin hub under Operations). Up to 6 per role, one Lagos calendar quarter each (`quarterBounds`), current or next. Only a claimed, listed profile can be picked (`isPublishedProfile`, the one seam for "published": change it with the trigger in the migration if profiles gain a publish step), and the person must hold the role (claimed, or a delivery record). `featured_profiles` has a before-insert trigger repeating the published and six-per-role rules, so a second writer cannot get around either. The read path filters on published AGAIN, because someone can go private after being picked.
- **On the rise this month**: computed, never typed. `runOnTheRiseSweep` is a passenger on `/api/cron/due-date-notifications`; it recomputes only when the Lagos month changed (marker in `app_settings` key `on_the_rise_month`) and stays empty until 30 days of `task_activity` exist, without marking the month so it looks again next day. Rules in `lib/featured-shelves.ts`: claimed and listed; a rollout went live in the last 90 days with them on it (`releaseLiveAt`, the recap-eligibility rule as a timestamp; test rollouts never count); their work was delivered (a `delivery_records` row; for a manager, who owns the rollout, one of theirs with an activity done); a manager also needs 2 or more teammates active on their rollouts in 30 days. Up to 6 per role, most recent first. Task activity logging started 2026-10-02, so the manager rule cannot qualify anyone before about 2026-11-01.
- **Order by viewer**: an artist meets management first, a manager meets the people who make the work first, a creative meets management first (`viewerKindFromProfile`). The seam for chat 1's profile type is the `profileType` argument there and the `loadViewerKind` call in `lib/featured-shelves-server.ts`; until then it reads claimed roles, and no claimed role reads as an artist. Someone Featured for a role is not repeated under On the rise for that role.
- **Never sold**: no price, plan or payment in the logic, routes or schema, held by `lib/featured-shelves-guard.test.ts`.
- **Not verified**: nothing has run against the real database or a real session. The migration was run on a real Postgres engine (PGlite) twice with 15 checks; the shelves were looked at in a throwaway page (deleted) at 375px and desktop with made-up people. `lib/press-kit-copy-guard.test.ts` fails 4 cases in a worktree whose folder name contains `directory-` (the guard matches that substring in the absolute path); none are in this change's files.
