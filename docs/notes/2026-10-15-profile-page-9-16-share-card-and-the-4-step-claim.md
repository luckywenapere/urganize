Relationships rebuild, design approved by the founder (mocks profile.html, claim.html in the coordinator project). Ships on, no flag (the page rides `NEXT_PUBLIC_FEATURE_DIRECTORY`, already on). No migration.

- **Claimed `/p/{slug}`** (`app/p/[slug]/page.tsx`): blurred-face cover, face, name + tick, role · city (`roleLine`), one hype line (the bio's first line, `hypeLine`), Managing faces + count (artists with `owner_user_id` = the person), stats, a credits grid, Reach + save. App dark tokens set on `.kit-island`'s variables inline. **Anything missing is hidden**: no photo hides the cover, no bio the hype line, no roster the Managing row, a zero its stat. **Vouches and Years have no data source, so they never render**; only Releases (distinct delivered or attested, visible credits, minus test rollouts and hidden credits) can. Dropped from the claimed page on purpose (bare-minimum design): availability pill, the delivered/claimed role lists, links. The unclaimed view is untouched.
- **Credits grid = cover art only** (`lib/person-page-extras-server.ts`). The 2026-09-05 "no release titles" rule still holds; covers are of releases that came out. If the founder wants covers off too, drop the grid.
- **Reach / +** (`components/people/ProfileActions.tsx`, `app/api/public-profile/reach`): the page never puts a user id in HTML, so after it draws a signed-in reader asks by slug. Reach opens the existing `WorkRequestSheet`; + inserts a `team_relationships` row pointing at the EXISTING profile (source 'manual'), never a new unclaimed one. Signed out, both go to `/auth?next=`. Hidden on your own page.
- **Share card** `GET /p/{slug}/card` (`route.tsx`, next/og, 1080x1920, public, 5-minute cache, same 404 as the page). Prints the real host (`app.urganize.app/p/x`), not `urganize.app`, which is the marketing site and has no `/p/`. Fonts via `loadRecapFonts`; `next.config.js` traces fonts for the route. `ShareStoryButton` fetches it before the tap (user activation) and hands the File to the share sheet; on the claim's last step and the owner's own page. Analytics method `story` added to `PROFILE_SHARE_METHODS`.
- **Claim** (`components/people/ClaimWizard.tsx`): Prove it's you (Work email, or Phone when the credit holds a phone) -> Enter code -> Make it yours (photo via the directory picker, hype line saved as bio, artists you manage via `/api/workspace/artists`) -> You're verified + Share to Story / View profile. Publishing is now always on at the end; the credits review ("Not mine") and availability steps are gone from the flow (the PATCH still supports `hideCredit`).
- **The code is stateless** (`lib/claim-code.ts`): HMAC of token + address + 10-minute window, keyed with the service-role key; valid for its window and the next. `POST /api/claim/[token]/code` checks the address through `checkClaimContact` (claim-server stays the only invites writer; a wrong address counts a try) and sends template `claim_code`. The redeem route passes `codeCheck`, so a TYPED email now needs the code (`bad_code` counts a try). Confirmed account email and typed phone go straight through, as before.
- **Instagram and X are not offered**: the proof rule is an email or phone already on the credit, and no credit carries a handle. Adding them needs a founder call on the proof rule plus Meta / X OAuth apps.
- **Not verified**: no browser pass, no real email sent, the card not rendered against real signed photo urls.
