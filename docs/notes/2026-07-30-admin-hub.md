- **Waitlist + Growth + Interviews are PORTS from apps/homepage**, re-gated behind the normal account login via `verifyAdmin`/`ADMIN_EMAILS` instead of the homepage's shared-secret cookie. They read the marketing site's **Neon** database directly: `@neondatabase/serverless` added to `apps/web`, `getNeonClient()` in `app/api/admin/_shared.ts`, backed by `GET /api/admin/{waitlist,growth,interviews}`. **Requires `DATABASE_URL` (the homepage's Neon connection string) set on the Vercel `Web` project** — unset, only those pages error. Growth's chart is plain CSS bars, deliberately NOT chart.js (boring stack).
- **Growth also shows new ACCOUNTS per month (2026-09-25, founder request: "analytics page should view monthly sign ups too").** A "New accounts" section now leads the page: 12 UTC calendar months of Supabase `profiles.created_at` (the house definition of a sign-up, the same table the Onboarding page's "Total signups" reads; every role counts), with Total / Last month / This month so far tiles, a chart and a table. It comes from its OWN route, `GET /api/admin/growth/accounts`, so `DATABASE_URL` now only affects the waitlist section below it; each section shows its own error. Four things not to undo: (1) it runs 13 exact HEAD counts (the total plus one per month) instead of reading rows, because PostgREST caps a response at max_rows (1,000 by default) and a row read silently undercounts past it; (2) a HEAD count that fails comes back from postgrest-js 2.101 with an empty message or as a 204 with no error, so `count === null` is a failure, never a zero; (3) running totals are worked BACKWARDS from the exact total and clamped at 0, so the table's last row always equals the Total tile; (4) month boundaries are built with `Date.UTC(y, m - n, 1)`, never by shifting a date with setUTCMonth, which skips February when today is the 31st. The month maths and the chart helpers are pure and tested (`lib/account-months.ts`, `lib/admin-bar-chart.ts`). Both charts on the page use one component, `components/admin/AdminBarChart.tsx` (one tab stop, arrow keys, a readout line instead of a number on every bar). This replaced PR #599's separate `/admin/signups` page, which was closed. **The waitlist "Last 12 weeks" tile was fixed the same day:** it took the last weekly total minus the FIRST one, but each point is a running total at the END of its week, so that only covered 11 weeks, and the table's first "Change" read "no change". `GET /api/admin/growth` now also returns `beforeWindow` (everyone on the waitlist before the first week began, a column of the same SQL statement so it reads the same `NOW()`), and `lib/waitlist-weeks.ts` measures the growth and every week's change from it, so the changes add up to the tile.

Worth knowing WHY it was missing for a month: `/admin/*` renders **no app chrome at all** — `AppShell`'s `showWorkspaceChrome` is `(isDashboardRoute || isSettingsRoute)`, so there is no topbar and no identity card here — and the 2026-07-30 pass above removed the per-page Back buttons on the reasoning that "the hub menu replaces them", which was true for moving BETWEEN admin sections and left nothing for leaving admin entirely. The browser Back button was the only exit. It sits ABOVE the item list, not inside it, because the list scrolls horizontally below `lg` and an exit that can scroll off the side of a phone is not an exit; it is never active and carries no `aria-current`. Labelled to match the identity card's own name for `/dashboard` so the two navs agree on what that surface is called, and `/dashboard` is hardcoded exactly as it is there — `HOME_PATH` is the post-authentication LANDING decision, not a nav href.
