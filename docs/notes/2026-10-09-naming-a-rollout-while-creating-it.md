# Naming a rollout while creating it (2026-10-09, v1.91.3, no flag)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

Found by using the live app: with type-first create on, tapping Single, EP or Album made the rollout on the spot, so there was no way to name it (every one was "Untitled rollout") and the cards locked the moment one was tapped. The UrgAns planner asks seven questions and none of them is the title, so the fix belongs on the create screen. **No flag and no schema change**: `POST /api/releases` already took a title.

- **The type-first screen now has a title field and a submit.** `CreateReleaseModal` opens on "What's it called?" (optional, 140 characters, focused on open, the same `input` class as the two-step form). The Single / EP / Album cards are a `role="radio"` group (arrow keys via `onRadioGroupKeyDown`) that stays changeable, and the footer's "Create rollout" creates it. That is one more tap than before, and it amends the 2026-09-01 "the tap IS the form" call. Pressing Create (or Enter in the title) with no card chosen says "Choose Single, EP or Album first." rather than defaulting to Single, because the planner skips its type question only for a type that was actually picked. With one playbook there is nothing to choose and it counts as picked. An empty title still saves as `DEFAULT_RELEASE_TITLE`, and `ReleaseSetupSheet` still asks for a name only while the title is a default.
- **The abandoned-shell discard accepts the created title.** `decideDraftDiscard` (`lib/release-draft-discard.ts`) used to require the default title, which would have kept every named-but-abandoned shell. It now treats the title as untouched when it is the default OR exactly (after trimming, case-sensitive) the title the rollout was created with. The created title comes from the create response (`savedTitle` in `onCreated`'s result), rides on the intake payload as `createdTitle` (set by `RolloutCreateFlow` and both `WorkspaceView` branches, beside `discardIfAbandoned`), and reaches the server as `?createdTitle=` through `buildDraftDiscardPath`. A blank, default or over-140 value is ignored, so an untitled shell sends exactly the v1.91.1 request. Every other condition is unchanged and still fails closed: planner_pending with no other metadata, draft, no date, description or cover, under an hour old, and zero activities, groups, files, songs, spend and collaborators. A rename after creation is a mismatch and keeps the rollout. Trust note: the caller vouches for the title, but only the owner can call this, only on their own rollout, and only one that is otherwise empty.
- **Not changed:** `AppShell`'s create (the global modal) still does not set `discardIfAbandoned`, as in v1.91.1 (**fixed in v1.92.1**, see the section of that name below). The planner's own type question stays skipped when the type was picked here; changing the type after the planner has opened is still not offered.
- **Tests:** `lib/release-draft-discard.test.ts` (named shells, renames, case, every other sign of work still winning, the request builder) and `lib/rollout-create-title-guard.test.ts` (a card pick never creates; the submit sends the title; every `discardIfAbandoned` carries `createdTitle`; the route reads it).
- **Not verified in a browser or against a real database.** Preview pass: Add rollout from the Catalogue and from Home, type a title, switch between Single, EP and Album, Create, and confirm the planner skips the type question and the catalogue shows the title; close the planner at Question 1 and confirm the named rollout is gone; then create another named one, rename it (or add an activity) in a second tab before closing the planner, and confirm it is kept.
