# Role-based views (2026-10-14, URG-260, v1.127.0, `NEXT_PUBLIC_FEATURE_ROLE_VIEWS`, ships on)

> Moved out of CLAUDE.md on 2026-10-22 (verbatim). "This file", "above", "below" and "the X section" in here refer to the old single CLAUDE.md: find the named section in docs/notes/README.md.

Founder-approved spec (2026-10-14). The menu leads with what a person's "Who are you?" answer needs. **Nothing is removed:** a tucked destination moves under a "More" group at the end of the menu, still opens from a deep link, and is still found by the command bar's search (`lib/app-pages.ts` is not filtered). Pure rules and tests in `lib/role-views.ts` / `role-views.test.ts`.

- **Resolution:** the Settings override (`profiles.role_view`) first, then `onboarding_persona` (music_manager → Artist manager, label_ar → Label, independent_artist → Solo artist, artist_team → Artist team, other and legacy producer_beatmaker → the full app), then `profiles.role` (artist → Solo artist, artist-manager → Artist manager, legacy **manager → Label**, founder: "yes old too"; artist-team and team-member → Artist team; anything else → the full app). Flag off = the full app for everyone.
- **Tucked per view:** Artist manager: Catalogue, Credits, Audience. Label: Opportunities, Shows. Solo artist: Artists, team assignment, People, Directory. Artist team: Artists, Catalogue, Credits, Opportunities, Audience, People, Directory. Home, Rollouts, Tasks, Press kits, Pitching, Notes and UrgAns are never tucked.
- **The nav filter** is `applyRoleView(buildShellAreas(flags), view)`: same areas, same order, minus what is tucked, plus a `more` area (an ordinary `ShellArea`, key `'more'`) holding the tucked tabs. An area that loses some tabs points its pill at its first remaining tab and stops claiming the tucked paths, so a deep link lights More. Every menu reads it through `components/shell/useShellAreas.ts`; the phone's More sheet appends `tuckedMoreItems`. `shell-nav.ts` only gained `'more'` in `ShellAreaKey`.
- **Not wired to UI yet (model only, `isTucked`):** Catalogue and Credits for managers and artist teams (the Catalogue area holds Rollouts, a default for everyone, so the area stays; there is no separate nav item to tuck), and team assignment for solo artists. The "one artist auto-selected" for a solo artist is what the artist filter already does when the roster has one artist.
- **Settings > General > View** (`RoleViewSection`): Automatic (shows what it resolves to) or any of the five views, saved on the user's own row by `updateRoleView` in `auth-store.ts`. **Needs `supabase/migrations/20261014120000_profiles_role_view.sql` applied** before the switch can save; until then profiles are read with `select('*')`, the column is absent, and everyone gets the automatic view.
